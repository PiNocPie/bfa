# Nen: มีอะไรในแอป และพรีเซนต์ยังไง

เอกสารทีม อัปเดต 2026-11-03 · เว็บตัวอย่าง: https://claude.ai/artifact/2KoUQs1Cn85hoskw6QcZMD

## ประโยคเดียว

**Nen คือร้านขาย API ให้ AI agent ซื้อทีละ call** ผู้ใช้ login ด้วย Google, เติมเงินด้วยบัตรหรือคริปโต แล้วออก API key ให้ agent โดยกำหนดวันหมดอายุและเพดานรายวันได้ agent หา API เอง ดูราคาก่อน จ่ายทีละ call และได้ใบเสร็จทุกครั้ง เบื้องหลังทุกบัญชีมีบัญชี NEAR ที่เป็นคนเซ็นจ่าย

## ปัญหา

- agent ต้องใช้ข้อมูลจากภายนอก แต่ API ส่วนใหญ่บังคับให้สมัคร ผูกบัตร ซื้อแพ็กรายเดือน และเก็บ key แยกเจ้าละตัว agent ทำเองไม่ได้
- ถ้าให้ agent ถือบัตรหรือ private key คนก็ไม่กล้าให้ เพราะไม่มีเพดาน ไม่มีวันหมดอายุ และตรวจย้อนหลังไม่ได้
- คนที่มี API ดีๆ อยากขายให้ agent แต่ไม่มีที่ลิสต์ที่ agent หาเจอและจ่ายเงินได้เอง

| ฟีเจอร์ | ทำอะไร | สถานะ |

| ค่า fee ตอนเติม | แสดงก่อนกดจ่าย: จ่าย $10 → fee 3% → เข้าบัญชี $9.70 | 3% เป็นตัวเลขร่าง ยังไม่ได้ตกลง |

### หน้าเว็บ

- **APIs & calls:** รายการ API ทั้งหมดที่ agent เรียกได้ แยกสถานะ Live / In review / Planned และรายการ 7 tools ที่ agent ใช้คุยกับ Nen
- **Connect an agent:** config สำหรับ Claude Code และ MCP client อื่น พร้อม prompt ตัวอย่าง
- **Sell an API:** ขั้นตอน 4 ขั้น พร้อมตัวอย่างรายงานจากบอท
- **Console:** Overview, API keys, Wallet, Usage

## API social (X, Instagram, TikTok): เริ่มจากต่อยอดของคนอื่นก่อน

แผนคือเปิดขาย API social ก่อนโดยต่อยอดจากผู้ให้บริการที่มีอยู่แล้ว ระหว่างนั้นค่อยหาทางทำของเราเอง ในเว็บใส่ไว้ 4 ตัว สถานะ Planned:
- X post search
- Instagram profile
- TikTok creator videos
- TikTok hashtag videos

ราคาต้นทางที่เห็นผ่าน Monid discover (2026-11-03) ถูกมาก: X search ~$0.0005–0.001/call, Instagram profile ~$0.001–0.015/call, TikTok ~$0.0006–0.0036/call เราจึงตั้งราคาต่อ call แบบคงที่ได้ เช่น จำกัดผลลัพธ์ไว้ 20 รายการต่อ call

**ข้อห้ามที่ต้องรู้ก่อน:** ข้อตกลงการใช้งาน (Terms) ของ Monid ฉบับ 16 ต.ค. 2026 ห้ามขายต่อหรือใช้เชิงพาณิชย์โดยไม่มีหนังสืออนุญาต และห้ามใช้ "as part of any effort to compete with us" แม้หน้า docs เรื่อง proxy จะบอกว่า "bill your own way… with or without markup" แต่ Terms ขัดกัน และ Nen เป็นคู่แข่งโดยตรง ดังนั้น:
1. **ห้ามขาย social API ผ่าน Monid จนกว่าจะได้หนังสืออนุญาต** ให้อีเมลไปขอ partnership ที่ support@monid.ai ก่อน
2. **ทางที่ปลอดภัยกว่า:** ต่อกับผู้ให้บริการต้นทางโดยตรง เช่น AnyAPI, TikHub, SerpApi หรือ Apify ซึ่งแต่ละเจ้ามี API ของตัวเอง ต้องอ่าน Terms เรื่องการขายต่อของแต่ละเจ้าก่อนเหมือนกัน
3. **ข้อมูล social มีความเสี่ยงทางกฎหมายของตัวมันเอง:** การ scrape X/Instagram/TikTok ขัดกับ Terms ของแพลตฟอร์มเหล่านั้น ต้องระบุแหล่งข้อมูลและ license ใน `nen.json` ทุกตัว

## ทำไมต้อง NEAR (ข้อนี้สำคัญที่สุดสำหรับ judge)

1. **ทุกคนที่ login ได้บัญชี NEAR** แม้จะ login ด้วย Google ก็ตาม คนใช้ไม่ต้องรู้เลย
2. **บัญชี NEAR เป็นคนเซ็นจ่าย USDC บน Base ผ่าน Chain Signatures:** ไม่มี private key ของ EVM อยู่ใน config เลย ต่างจากคู่แข่งที่ให้ใส่ `AGENT_PRIVATE_KEY`
3. **NEAR Intents สำหรับเติมเงิน:** จ่ายจากเชนไหนก็ได้ ระบบแปลงเป็น USDC ให้
4. **Treasury contract บน NEAR (กำลังทำ):** บังคับเพดานการใช้จ่ายบนเชน ไม่ใช่แค่ในเซิร์ฟเวอร์เรา
5. **มีหลักฐานจริง:** มี tx บน Base Sepolia ที่บัญชี NEAR testnet เป็นคนเซ็น เปิดดูได้บน basescan

ประโยคปิดสำหรับ judge: *"หน้าบ้านเหมือนแอปทั่วไป มี Google กับบัตร หลังบ้านทุกบัญชีเป็นบัญชี NEAR ที่เซ็นจ่ายข้ามเชนได้"*

## โมเดลรายได้

- **Fee ตอนเติมเงิน** (ร่างไว้ 3%) ผู้ใช้เห็นก่อนกดจ่ายทุกครั้ง
- **ไม่บวกราคาต่อ call:** agent จ่ายราคาเดียวกับที่ seller ตั้ง เงินเข้า seller ตรง
- ต่อยอดได้ทีหลัง: listing ที่ผ่านการยืนยันตัวตน (verified-provider) หรือแพ็กสำหรับทีม

## สิ่งที่ต้องพูดตรงๆ (ถ้า judge ถาม)

- **ตอนนี้อยู่บน testnet ทั้งหมด** การตัดบัตรผ่าน Privy ใช้ได้แค่ mainnet บน testnet จึงเดโมได้แค่หน้าจอ
- **Login, เติมเงิน และ API key ตอนนี้เป็นหน้าจอตัวอย่าง** ที่ใช้ได้จริงคือ MCP server, การจ่ายเงิน, ใบเสร็จ, registry และบอท
- **ใครถือเงิน:** ถ้าเติมด้วยบัตรแล้วหัก fee แบบนี้ Nen ต้องรับเงินก่อนแล้วค่อยเติมให้ ซึ่งแปลว่ามีช่วงที่ Nen ถือเงิน ทางที่ดีกว่าคือให้เงินไปอยู่ใน address ที่บัญชี NEAR ของผู้ใช้คุม แล้วให้ treasury contract บังคับเพดาน **ทีมต้องตัดสินใจเรื่องนี้ก่อนวันส่ง**
- **Nansen ยังไม่ผ่านรีวิว** และยังไม่ได้จ่ายจริงบน mainnet ส่วน Elfa ยังอยู่ในแผน ต้องคุยเป็น partner หรือให้ผู้ใช้ใส่ key ของ Elfa เอง

## ก่อนวันส่ง (14 พ.ย.) ต้องมี

1. Demo seller กับ gateway อยู่บน https
2. ต่อ Privy: Google login + กระเป๋า NEAR
3. Backend ของ API key: วันหมดอายุ, เพดานรวม, เพดานราย API
4. Treasury contract บน NEAR
5. คลิปเดโม 3 นาทีตามสคริปต์ข้างบน + โพสต์ X
6. เปิด repo เป็น public และสแกน secret ใน history
